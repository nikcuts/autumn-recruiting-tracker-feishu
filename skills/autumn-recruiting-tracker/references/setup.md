# 首次设置向导

首次使用先识别操作系统，并向用户说明：核心链路是用户自己的飞书多维表格和飞书日历；本地日历、邮箱等均为可选项。

## 1. 询问必要信息

依次确认：

1. 使用飞书还是 Lark；
2. 已有秋招 Base/Wiki 链接，还是新建；
3. 目标表和飞书主日历或指定日历；
4. 是否接受提前 24 小时/1 小时提醒、每日摘要和 7/14 天停滞提醒。

一次只问一组相关问题。不要索要令牌、密码或验证码。不要在首次设置中强制配置本地邮箱或本地日历。

## 2. 安装与授权

检查 `lark-cli` 与 Node.js/npm。缺少时使用飞书官方项目 [larksuite/cli](https://github.com/larksuite/cli) 的推荐安装方式，并在浏览器授权页面等待用户本人确认。使用用户身份访问资源（`--as user`）。

## 3. 解析资源

对用户提供的 Base/Wiki URL 使用 CLI 的 URL 解析命令取得真实 `base_token`、`table_id` 和 `view_id`，不要从 URL 字符串猜测。先读取表字段和飞书日历确认访问，再接受第一条记录。

## 4. 验收与保存

把资源坐标和偏好保存为本机 `config.local.json`，不保存密钥。只读验证登录、Base、目标表和飞书日历；未启用的可选能力标记为“未配置”，不视为失败。

## 5. 后续可选集成

用户明确要求时再配置本地日历或邮件。macOS 使用已授权的 Calendar/Mail 接口；Windows 不假定存在统一接口，只有当前环境有受支持的 Outlook/Microsoft 365 连接器且用户授权后才启用，否则继续只使用飞书。
