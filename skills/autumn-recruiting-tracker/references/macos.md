# macOS 可选模块

本模块只适用于用户明确启用 macOS Calendar 同步、Mail.app 招聘邮件监控或定时巡检的场景。默认关闭。它不改变飞书核心设置，也不要求用户把邮箱密码、授权令牌或私人邮件复制到聊天中。

## 启用前确认

先向用户说明将要启用的能力，并分别确认：

1. 是否同步 macOS Calendar；若是，读取日历名称后由用户选择目标日历；
2. 是否监控 Mail.app；若是，读取账户名称和地址后由用户选择目标账户；
3. 是否创建定时巡检；默认建议每小时一次，只有用户确认后才创建；
4. 是否接受只读边界：不标记已读、不回复、转发、移动、删除、归档、加旗标或下载附件。

配置只保存 `provider`、用户选择的日历/账户标识和偏好；不要保存邮箱密码、Cookie、Message-ID 历史或邮件正文。

## macOS Calendar

使用 Calendar 的 JXA（`osascript -l JavaScript`）接口：

1. 先读取 `Application("Calendar").calendars()` 的名称，让用户选择；不要假定存在名为“个人”的日历。
2. 新建或更新前，按公司、事项类型、岗位和时间搜索同一事项，命中唯一事件时更新，避免重复创建。
3. 有明确起止时间时原样写入；只有日期时创建全天事项；用户说“暂定”时保留标识。
4. 写入至少维护标题、开始时间、结束时间、全天标记、描述和链接；使用带时区的 ISO 8601 时间。
5. 写入后重新读取并核对事件。若系统拒绝自动化权限，停止本地写入，提示用户在“系统设置 → 隐私与安全性 → 自动化”中允许 Codex/终端控制 Calendar。

飞书日历与 macOS Calendar 中的同一事项是镜像副本，不算冲突。比较不同事项时，使用 `A.start < B.end && A.end > B.start`；全天事件按实际日期范围参与检查。

## Mail.app 只读监控

使用 Mail 的 JXA 接口：

1. 读取账户名称和地址，只展示账户元数据供用户选择；不能自动选择作者或默认账户。
2. 只检查用户选定账户的 INBOX 及最近时间窗口（建议 70 分钟）内的新邮件。
3. 优先读取主题、发件人、收件时间、Message-ID；只有判断为招聘邮件时才读取必要正文片段。
4. 识别投递确认、测评、笔试、面试、改期、截止时间、拒信、Offer 和签约通知。
5. 按 Message-ID 和已报告事项去重。新招聘邮件先通知用户，等待用户确认后再更新飞书表格或日历。
6. 非招聘邮件忽略，不读取或报告其正文。不得下载附件。

如果账户不存在、INBOX 不可读或 Mail 自动化权限失败，只报告需要用户处理的故障和修复路径，不要尝试修改邮箱状态。

## 定时巡检

只有用户确认后才创建 Codex heartbeat/automation。创建前展示频率、监控账户/日历和通知规则。可使用以下脱敏提示词：

```text
每小时只读检查我明确选择的 macOS Mail.app 账户和 Calendar。邮件只看最近 70 分钟，按 Message-ID 去重；只报告新的招聘邮件，不修改邮箱状态。同步事项时合并飞书与 macOS 日历镜像，检查未来 72 小时冲突，并在约 24 小时和约 1 小时前提醒未完成的测评、笔试和面试。没有需要处理的变化时保持安静。
```

定时任务不得把账号密码或私人邮件正文写入提示词。用户要求停止时，删除对应 automation/heartbeat，并保留已有数据不变。

## 权限和故障边界

- Calendar 写入失败时，可以保留已经成功的飞书写入，但必须明确报告本地未同步。
- Mail 读取失败不影响飞书表格和日历功能。
- 任何删除、移动、改期或发送邮件的请求都超出本模块的默认只读范围，必须单独获得明确授权。
