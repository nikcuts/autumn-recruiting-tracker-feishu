# 秋招进度与飞书同步

把用户确认的秋招事项维护在其自己授权的飞书多维表格和飞书日历中。首次使用或配置失效时，先读取 [首次设置向导](references/setup.md)，完成交互和只读验收后再写入数据。macOS 用户明确启用本地同步或邮件监控时，再读取 [macOS 可选模块](references/macos.md)。

## 工作边界

- 仅操作用户明确指定或在首次设置中确认的 Base、表格和日历；不要猜测资源坐标。
- 用户说“已投递”时，按公司与岗位查重后创建或更新一行，不制造重复记录。
- 用户提供测评、笔试或面试时间时，更新投递进度和笔面试提醒，并写入飞书日历；只有用户启用且平台支持时才同步其他日历。
- 日历写入前搜索同一事项；明确起止时间按原值保存，只有日期时创建全天事项，不擅自猜测时间。
- 用户说“暂定”时保留暂定标识；改期时更新原事项。
- 任何结构变更、删除、邮件写入或权限变化先说明影响并获得确认。
- 写入后读取目标验证；任一副本失败时如实报告，不声称全部同步成功。

## 学习与辅助功能

- 只读检查未来 72 小时的真实日程冲突，跨日历的同一事项镜像不算冲突。
- 对未完成且时间明确的测评、笔试和面试提供约 24 小时及约 1 小时提醒；按事项去重，已完成事项不提醒。
- 可按投递日期检查“已投递”岗位的 7/14 天停滞，但不自动发送跟进邮件。
- 用户提供 JD 时，提炼职责、必备技术、加分项和准备重点；没有简历证据时不得猜测经历。

## 安全

不要索要或保存 access token、app secret、密码、验证码、Cookie 或完整私人邮件正文。个人配置只能保存在本机 `config.local.json`，不得提交到仓库。默认只配置飞书 Base 与飞书日历；Windows 本地邮件/日历能力只有存在受支持连接器并经用户授权时才启用。

详细流程见 [references/setup.md](references/setup.md)。

## macOS 可选模块

仅当用户明确要求 macOS 本地日历同步、Mail.app 监控或定时巡检时启用。先读取 `references/macos.md`，发现并让用户选择本机日历/邮箱账户，不能使用仓库作者的账户名、邮箱地址或日历名称。模块默认关闭，不影响飞书核心链路。
